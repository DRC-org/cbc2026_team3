# 機構引き継ぎチェックリスト — 機構が付いた日に埋める値

**機構担当と制御担当が一緒に上から潰すための表。** 制御側の数値は今のところ
「**機構が付いていない状態で誰かが起動しても壊れない**」ことだけを狙った安全側の
微小値で、**確定しているのは `y_axis` の `scale` ただ 1 つ**である。

この一覧が無いと、当日は「動かしてみて、おかしいところだけ直す」ことになる。
それでは**危険な向きに間違っている値ほど、壊してからでないと気付けない**。

> 手順（値をどう測るか・どう反映するか）は `docs/impl_plan.md` の
> 「Phase 5 > 機構完成後にやること」。**この表は「何を埋めるか」の棚卸し**で、
> 埋め方はあちらを見る。設計の理由は `CLAUDE.md`。

---

## 0. 最優先の 2 つ — **これだけは機構が付いた日のうちに**

他は「動かない・届かない」で済むが、この 2 つは**壊す向き**に間違っている。
どちらも「広すぎる」ことが危険で、広すぎても平常時は何の症状も出さない。

| 対象 | 現在値 | 場所 | 何が起きるか |
|---|---|---|---|
| `y_axis` の `homing.search_distance` | **22.0mm** | `config/main_hand_positions.yaml` | **広すぎると機構端まで押し込む。** 「当たるまで動かす」動作に対する唯一の無人の歯止めで、配線が抜けたセンサは「いつまでも当たらない」形でしか現れない。実測ストローク全長 + わずかな余裕へ詰める |
| サーボの `kProvisionalLimits` | **`{0.0, 30.0, 90.0}`**（0〜30deg / 90deg/s） | `firmware/servo/include/config.h` | **広すぎるとサーボが機構に当たったまま押し続けて焼損する。** 名前のとおり暫定値。実可動域が決まったら**すぐに**狭める。ファームを焼き直すので、当日の作業順で後回しにしないこと |

**`search_distance` を詰めるときは `manual` の `min`/`max` も同時に実測へ寄せる。**
片方だけ動かすと「原点に届かない」か「宣言した可動範囲の外まで押し込む」のどちらかになる。
現在値 22.0 は `manual` の全幅（`20.0 - (-2.0)`）に合わせてあり、可動範囲の上端から
始めても下端までは必ず届き、下端より先へは行かない。

## 1. メインハンド（`config/main_hand_positions.yaml`）

| 対象 | 現在値 | 危険の向き / 注意 |
|---|---|---|
| `positions.y_axis` | 全ストローク **0〜15mm**（home 0 / work_1 5 / work_2 7.5 / work_3 10 / work_shared 15） | **`work_1`(5.0) と `place`(5.0)、`work_shared`(15.0) と `approach`(15.0) が同値。** 同じ場所という意味ではなく、微小値を機械的に割り振った結果たまたま一致しているだけ。**1 つずつ独立に測って埋める** |
| `positions.y_axis.approach` / `.place` | 15.0 / 5.0 | **試合シーケンスから未参照**（戦略未確定のため残してある）。使うかどうかを機構が付いた日に決める |
| `axes.y_axis.scale` | **55.0131** | **唯一の確定値**（モジュール 1 / 歯数 40）。組み立て後に一度だけ実測で確かめる。**測るときは必ず同じ方向から寄せる**（往復するとバックラッシュが `scale` の誤差に紛れる） |
| `axes.y_axis.manual` | **−2.0〜20.0mm** | 物理端ではなく**その内側**に取る。上の `search_distance` と対で動かす |
| `axes.y_axis.tolerance` / `sync_tolerance` | 1.0mm / 2.0mm | `sync_tolerance` を緩めるのは最後の手段。左右直結なのでずれはその場で機構を壊す |
| `axes.y_axis.timeout_s` | 4.0s | 実動作時間 + 余裕へ |
| `positions.rotate` | **0〜8deg**（home 0 / pick 8 / place 0） | **干渉角が未確認。** エンドエフェクタが他の機構に当たらない範囲を先に決める |
| `axes.rotate.manual` | **−5.0〜15.0deg** | 同上。干渉しない範囲へ詰める |
| `axes.rotate.homing` | **コメントアウト（有効化できない）** | スイッチ未装着に加え、**載せるスロットが無く**（サーボ基板 #0 は SV0〜SV4 の 5 本とも使用中）、**EDULITE には原点確定の経路そのものが無い**。詳細は `docs/checks_and_health.md` の「零点確定」節 |
| `motors.rotate_r` / `.rotate_l` の `set_zero_on_start`（`config/main_hand.yaml`） | **`true`（暫定）** | 上の `homing` が入るまでの代替。**EDULITE の原点はフラッシュの機械ゼロで、2 台のゼロが揃っていないと物理的にずれ 0 でも逆換算後に差として出る**（実機で 175.879deg → 起動直後に全体緊急停止）。起動のたびに `set_zero` を送って電源投入時の姿勢を原点にしている。**機構が付いたら「起動前に rotate を収納姿勢へ戻す」ことが人の責任になる。** `homing` を有効化する日に 2 台とも `false` へ戻すこと（左右で値が食い違うと揃うどころか偏差が残る） |
| `positions.gripper` / `wall_f` / `wall_r`（サーボ 3 軸） | **0〜6deg**（gripper 0/5、wall 0/3/6） | **実可動域が未確認。** 上の `kProvisionalLimits` と必ずセットで決める（ファームが黙ってクランプするので、超えた値は「送ったのに途中で止まる」としか現れない） |
| `positions.wall_r.closed` / `.open` | 3.0 / 6.0 | **試合シーケンスから未参照**（後壁を使う手順が未確定）。動作確認は 3 状態とも駆動する |
| `positions.conveyor.run` | **0.3 duty** | ファーム側 `max_duty` でクランプされる。ここだけ上げても効かない |
| `axes.conveyor.settle_s` | 0.5s | DC 基板は到達を報告しないので、この固定待ちが唯一の間 |

## 5. 埋め終わったら

1. `uv run pytest` — 値だけを変えたぶんはテストの追随不要。ただし**軸名・位置名を
   増減した / `robots/*.py` のステップ名やラベルを変えた場合は追随が要る**
   （`docs/impl_plan.md` の「Phase 5 > 機構完成後にやること」の表を参照）
2. `scripts/setup_can.sh --strict` が全バス起動で通ること
3. **`--dry-run` ではなく実機で動作確認シーケンスを 1 回通す。**
   ホーミングを含む全アクチュエータが順に動く
4. `config/checklist.yaml` の指差喚呼を上から 1 回読み上げる。
   特に `sub_lift_holds`（自重落下）と `estop_functional`（非常停止が効くこと）
